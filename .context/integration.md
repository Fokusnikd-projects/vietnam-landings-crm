# Интеграция с Google Таблицей

`src/data.js` задаёт spreadsheet ID, gid и имя листа «Лиды», парсит строку заголовков и сопоставляет `№` с номером текущей строки. Стадия разбирается из «Статус» по шаблону (`02 …`, `?`, `✕`, пусто); без этого столбца используется «Готовность». Телефон, Zalo и WhatsApp нормализуются в цифры `84…`. Кэш-ключ листа — `lead-crm:sheet-cache:v2`. `src/App.jsx` загружает диапазон `A:ZZ`, чтобы новый столбец не потерялся; поля по-прежнему ищутся по заголовку. `src/googleSheet.js` даёт `writeCell` поверх `buildWriteRanges`: смена стадии пишет одну ячейку, конфликт (другой номер строки, изменённая ячейка, формула) отменяет запись. Перед POST `values:batchUpdate` с `RAW` приложение перечитывает значения и формулы строки; после отказа или успеха лист читается снова и открывается тот же №. Это проверка перед записью, а не атомарная блокировка от гонки между проверкой и POST.

Нельзя отправлять файл `src/snapshot.json` на Vercel или импортировать его в клиентскую сборку. Проверять `npm run build:vercel`, `node --test tests/data.test.mjs tests/googleSheet.test.mjs`, отсутствие имени из снимка в `dist/client` и браузерный поток с мокированным Google API. Реальный OAuth и запись требуют настроенного Client ID.
